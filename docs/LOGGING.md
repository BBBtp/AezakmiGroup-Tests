# Диагностическое логирование Playwright

## Цель

По логу должно быть понятно: какой тест выполнялся, на каком URL, какое действие выполнялось, какой локатор использовался, что ожидалось и что произошло фактически.

## Формат

```text
[PW][ACTION] test="..." url="..." action="click" target="login submit" locator="[data-testid=...]"
[PW][EXPECT] target="login container" locator="..." expected="visible"
[PW][FAIL] action="click" target="..." locator="..." url="..." error="..."
```

## Обязательные правила

- Не использовать голые `click`, `fill`, `check` в новых Page Objects, если действие можно обернуть диагностическим helper.
- Для динамического локатора указывать человекочитаемую цель: например `AB tests row: edit`.
- Перед навигацией писать целевой URL.
- При ошибке сохранять текущий URL и короткое состояние локатора: count, visible, text.
- Значения паролей и токенов никогда не писать в лог.

## Где искать причину

1. `[PW][FAIL]` — последнее действие.
2. `locator` и `target` — какой элемент ожидался.
3. `url` — на какой странице выполнялся шаг.
4. Playwright trace/screenshot — визуальная проверка состояния.
5. Allure — последовательность шагов и итог для DoQA.
