# Диагностическое логирование Playwright

## Цель

По Allure-отчёту и stdout должно быть понятно: какой тест выполнялся, на каком URL, какое действие
выполнялось, какой элемент использовался, что ожидалось и что произошло фактически.

Каждый тест отображается как `[TC-<DoQA ID>] <бизнес-результат>`, содержит Markdown-описание,
теги CRM/E2E/smoke|regression/project/domain и последовательность AAA-шагов.

## Формат

```text
[ПОДГОТОВКА] контролируемые данные, mock или предусловие
[ДЕЙСТВИЕ] пользовательское действие
[ПРОВЕРКА] наблюдаемая проверка
[PW][ACTION] test="..." url="..." action="click" target="login submit" locator="[data-testid=...]"
[PW][EXPECT] target="login container" locator="..." expected="visible"
[PW][FAIL] action="click" target="..." locator="..." url="..." error="..."
```

## Обязательные правила

- Не использовать голые `click`, `fill`, `check` в новых Page Objects, если действие можно обернуть диагностическим helper.
- `UiActions` создаёт шаг `ДЕЙСТВИЕ`, `UiExpectations` и `scenarioCheck` создают шаг `ПРОВЕРКА`,
  а контролируемые сетевые ответы создают шаг `ПОДГОТОВКА`.
- Название шага и его человекочитаемая цель пишутся по-русски. Без перевода остаются только
  названия элементов интерфейса, URL, HTTP-методы и технические идентификаторы, если это нужно
  для однозначной диагностики.
- В расширенном описании используются разделы «Цель», «Контекст», «Предусловия», «Сценарий» и
  «Ожидаемый результат»; отдельный раздел «Диагностика» запрещён.
- В `tests/smoke` и `tests/regression` запрещены импорт `@playwright/test`, raw `expect()`,
  `locator` и `getBy*`. UI-проверка оформляется методом page/component, проверка чистых данных —
  методом `scenarioCheck` или доменного support-контракта.
- Название каждого теста начинается с `[TC-<ID>]`; ID обязан совпадать с единственным
  `allure.allureId('<ID>')`.
- Для динамического локатора указывать человекочитаемую цель: например
  `строка A/B-теста: редактирование`.
- Перед навигацией писать целевой URL.
- При ошибке сохранять текущий URL и короткое состояние локатора: count, visible, text.
- Значения паролей и токенов никогда не писать в лог.

## Где искать причину

1. `[PW][FAIL]` — последнее действие.
2. `locator` и `target` — какой элемент ожидался.
3. `url` — на какой странице выполнялся шаг.
4. Playwright trace/screenshot — визуальная проверка состояния.
5. Allure — последовательность шагов и итог для DoQA.
